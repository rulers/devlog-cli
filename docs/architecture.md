# Architecture

## 状態と目的

本書はGo製CLIのMVP設計です。Go moduleとCLI入口・ヘルプ・引数検証を実装済みです。コマンド処理とCIは未実装です。完成時は既存のNotion日記DBへ、ユーザーが確認した作業ログを1件追加します。

## 最小構成

```text
対話入力 → ログの構造化 → 本文・プロパティ生成 → プレビュー・確認
                                                    ↓
                                            ntn → Notion → URL表示
TOML設定 ───────────────────────────────────────→ ntn → Notion
環境変数 / ntnの認証ストア ────────────────────────↗
```

実装は `cmd/devlog/main.go` を入口とします。処理が増えたら `internal/config`、`internal/logentry`、`internal/notion` に責務を分けます。先に空のレイヤーや汎用クライアントを作りません。

- Go: コマンドの振り分け、設定読み込み、入力、検証、本文生成、プレビュー、結果表示。
- ntn: Notion APIへの通信と認証。Goから `os/exec` で呼び出す。
- Notion: 既存データソースにページを保持する。DB作成・スキーマ変更は行わない。

## 設定と投稿先

設定は `--config <path>` を優先し、指定がなければ `config/local.toml` を読みます。設定がない、プレースホルダーのまま、必須値が空の場合は投稿前に失敗させます。設定のキーは [example.toml](../config/example.toml) と揃えます。

Notionへのページ作成では投稿先の `data_source_id` を使う予定です。DB IDと区別して取得します。必要な既存プロパティはタイトル（title）、日付（date）、タグ（multi_select）。名前は設定から読み、型を検証します。タグは既存の選択肢を使用し、不足時は診断で設定・DB側の準備を案内します。

プロジェクトはタイトルに含め、専用プロパティはMVPでは要求しません。日付は実行端末のローカル日付を使い、プレビューに表示します。

## コマンドの流れ

### add

1. 設定を検証し、ntnと投稿先へのアクセス・スキーマを確認する。
2. プロジェクトとログ項目を対話入力する。プロジェクトと「今日やったこと」は必須、残りは任意とする。
3. タイトル、日付、タグ、本文を生成する。本文の項目順はREADMEに合わせる。
4. 投稿先と内容を表示する。確認の既定値はキャンセルとし、EOFや中断でも投稿しない。
5. ntn経由で1回だけ作成を要求し、応答からページURLを取得する。
6. 成功時はURLを表示、失敗時は秘密情報を除いた理由と非ゼロの終了コードを返す。

### doctor

設定、ntnの存在と対応バージョン、認証、データソースへの読み取りアクセス、プロパティ名・型・タグを検証します。テストページは作りません。読み取り診断だけでは書き込み成功を保証できないため、最終確認はテストDBへの許可された投稿で行います。

### config

設定ファイルの場所と検証済み設定を表示します。環境変数やntnの認証情報は出力しません。設定編集・初期生成はMVP外です。

## ntnとの境界

公式の[概要](https://developers.notion.com/cli/get-started/overview)と[認証](https://developers.notion.com/cli/get-started/authentication)を参照します。利用するAPIコマンド、JSON入出力、対応バージョンは実装時に確認し、READMEへ記録します。

引数配列で起動し、シェルを介しません。ユーザー本文はJSONとしてエンコードし、標準入力等で渡します。実行にはタイムアウトを設け、終了コードと応答を確認します。トークンは環境から引き継ぐかntnの認証ストアを利用し、devlog自身では読み出して保存しません。

作成要求後のタイムアウト・通信切断では、ページが作成済みの可能性があります。MVPは自動リトライを行わず、投稿先確認後の手動再実行を案内します。投稿結果が不明な場合や応答にURLがない場合に成功扱いをしません。

## 検証と今後

設定・本文・入力検証・キャンセルは単体テスト、ntnの境界は代替実行で確認します。通常のテストとCIはNotionへ接続しません。実投稿は許可されたテスト用DBで、件数、本文、プロパティ、URLを確認します。

最低Goバージョンは1.22で、CLI骨格は標準ライブラリのみを使用します。TOMLライブラリ、ntn対応バージョン、具体的なAPI呼び出しは実装時に確定します。将来のGit連携、引数入力、Markdown入力は実利用の必要に応じて追加します。判断と理由を残す必要がある場合は `docs/decisions/` に短い記録を追加します。
