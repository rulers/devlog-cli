# Architecture

## 状態と目的

本書はGo製CLIのMVP設計と実装状況です。Go moduleとCLI入口・ヘルプ・引数検証、`config` のTOML読み込み・検証・表示、`doctor` の読み取り診断を実装済みです。`add` は対話入力・Markdown生成・プレビュー・確認まで実装済みですが、確認後も投稿しません。Notionへの投稿とURL表示は未実装です。GoのQuality GateをGitHub Actionsで実行します。

## 最小構成

```text
対話入力 → ログの構造化 → 本文・プロパティ生成 → プレビュー・確認
                                                投稿は未実装
TOML設定 ──────────────→ add (既定値・プレビュー設定)
        └──────────────→ doctor (読み取り専用)
環境変数 / ntn認証 ────→ doctor
```

実装は `cmd/devlog/main.go` を入口とします。処理が増えたら `internal/config`、`internal/logentry`、`internal/notion` に責務を分けます。先に空のレイヤーや汎用クライアントを作りません。

- Go: コマンドの振り分け、設定読み込み、入力、検証、本文生成、プレビュー、結果表示。
- ntn: `doctor` の読み取り診断で通信・認証を担う。将来の投稿にも使用する。現在の `add` からは呼び出さない。
- Notion: 既存データソースにページを保持する。DB作成・スキーマ変更は行わない。

## 設定と投稿先

設定は `--config <path>` を優先し、指定がなければ `config/local.toml` を読みます。設定がない、プレースホルダーのまま、必須値が空の場合は入力前に失敗させます。`defaults.project` があれば `add` のプロジェクト既定値として使います。設定のキーは [example.toml](../config/example.toml) と揃えます。

Notionへのページ作成では投稿先の `data_source_id` を使う予定です。DB IDと区別して取得します。必要な既存プロパティはタイトル（title）、日付（date）、タグ（multi_select）。名前は設定から読み、型を検証します。タグは既存の選択肢を使用し、不足時は診断で設定・DB側の準備を案内します。

プロジェクトはタイトルに含め、専用プロパティはMVPでは要求しません。日付は実行端末のローカル日付を使い、プレビューに表示します。

## コマンドの流れ

### add

1. `loadConfig` で設定を読み込み・検証する。Notionやntnへのリクエストは行わない。
2. プロジェクトとログ項目を対話入力する。プロジェクトと「今日やったこと」は必須、残りは任意とする。
3. タイトル、ローカル日付、設定済みタグ、本文を生成する。本文の項目順はREADMEに合わせ、空の任意項目は省略する。
4. 投稿先・タイトル・日付・タグ・本文を表示する。確認の既定値はキャンセルとし、明示確認後も投稿せず未実装であることを表示する。キャンセルとEOFは終了コード3で終了する。

### doctor

設定、ntnの存在と対応バージョン、認証、データソースへの読み取りアクセス、プロパティ名・型・タグを検証します。テストページは作りません。読み取り診断だけでは書き込み成功を保証できないため、最終確認はテストDBへの許可された投稿で行います。

### config

設定ファイルの場所と検証済み設定を表示します。環境変数やntnの認証情報は出力しません。設定編集・初期生成はMVP外です。

## 終了コード

- `0`: 正常終了。`add` はプレビュー確認後も投稿せず終了します。
- `1`: 設定、入力、その他の実行時エラー。
- `2`: 引数エラー。
- `3`: `add` のキャンセルまたはEOF。EOF時は部分入力を採用しません。

## ntnとの境界

投稿機能を実装する際は、公式の[概要](https://developers.notion.com/cli/get-started/overview)と[認証](https://developers.notion.com/cli/get-started/authentication)を参照します。利用するAPIコマンド、JSON入出力、対応バージョンは実装時に確認し、READMEへ記録します。現在の `add` はこの境界を呼び出しません。

将来の投稿処理は引数配列で起動し、シェルを介さず、ユーザー本文をJSONとしてエンコードして標準入力等で渡します。トークンは環境から引き継ぐかntnの認証ストアを利用し、devlog自身では読み出して保存しません。

作成要求後のタイムアウト・通信切断では、ページが作成済みの可能性があります。MVPは自動リトライを行わず、投稿先確認後の手動再実行を案内します。投稿結果が不明な場合や応答にURLがない場合に成功扱いをしません。

## 検証と今後

設定・本文・入力検証・プレビュー・キャンセル・確認後も投稿しないことは単体テストで確認します。通常のテストとCIはNotionへ接続しません。実投稿機能は未実装です。

最低Goバージョンは1.22です。TOMLにはBurntSushi/toml v1.4.0を使用し、未知キーと不正値を拒否します。ntnは0.23.19で検証し、他バージョンは診断で拒否します。doctorはusers/meとdata_sources/<id>へ明示的なGETを行い、各実行に15秒のタイムアウトを設けます。標準入力は渡さず、ntnのエラー出力は破棄します。投稿APIは別途 add 投稿機能を実装する際に確定します。将来のGit連携、引数入力、Markdown入力は実利用の必要に応じて追加します。判断と理由を残す必要がある場合は `docs/decisions/` に短い記録を追加します。
